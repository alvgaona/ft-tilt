<p slot="lede" class="lede">A flat hexacopter that loses one motor can no longer produce every torque, because its motors only push. Tilting each rotor toward the vertical axis fixes that for 4.4 % of the thrust. We rebuilt the vehicle of Giribet et al. [@rpic17; @icris18] in Gazebo [@gz], with the papers' 200 Hz flight software as a plugin and Aerostack2 [@as2] on ROS 2 [@ros2] flying it from above.</p>

<p class="note">The pseudo-inverse saturates motor 2 at its cap, so the torque it was meant to give is simply lost. The null-space allocation lowers motor 5, opposite the fault, to match, and keeps the torque balance. With this partial fault the allocation, not the tilt, decides the outcome (derived); RPIC17 flew the pair as standard + pinv and tilted + fault-aware (assumed).</p>

### Companion computer

- **Motion controller**: a pluginlib plugin for Aerostack2's controller manager. POSITION and SPEED in, ATTITUDE out. It moves its reference toward the target no faster than the behaviour's speed limit, so it never jumps.
- **Platform**: an `as2::AerialPlatform` that takes ATTITUDE only and declares it in the `earth` frame, so any spawn yaw works. A negative thrust disarms.
- **State estimator**: Aerostack2's ground-truth plugin, fed by the platform from Gazebo's odometry.

</div>
<div>

### Flight controller

- **One gz-sim system**, `FtTiltController`: the papers' loop at 200 Hz. It reads the rotor geometry from the model, so the allocation matrix always matches what Gazebo simulates.
- **All the maths** is in `ft_tilt_control`: plain C++/Eigen with no ROS or Gazebo, tested against the papers' closed forms. It could go on a flight computer as is.
- **The fault is known**, as in the papers (an RC switch there): `motor_health` switches the allocator and the gain set in the same tick.

<div class="prop">
<b>Position loop</b> <span class="note">(stands in for the papers' RC pilot; not in the papers)</span>
<dl class="eq">
  <dt>Acceleration</dt>
  <dd>$a = K_p e + K_i\!\int\! e\,dt + K_d (v_r - v)$</dd>
  <dt>Attitude</dt>
  <dd>$\theta_r = \operatorname{atan2}(a_{\mathrm{fwd}}, g),\ \ \phi_r = -\operatorname{atan2}(a_{\mathrm{left}}, g)$</dd>
  <dt>Thrust</dt>
  <dd>$T = \dfrac{m\,(g + a_z)}{\cos\phi\,\cos\theta}$</dd>
</dl>
<p class="note">Tilt ≤ 10°, position error capped at 2 m. The integral (≤ 0.5 m/s²) cancels the ≈ 0.2 m/s² sideways push that tilted rotors make once their forces are unequal; $A$ has no rows for it.</p>
</div>
<div class="prop">
<b>Attitude PID</b> <span class="note">(ICRIS18 [@icris18] §IV)</span>
<dl class="eq">
  <dt>Torque</dt>
  <dd>$M = K_p e_\eta + \int K_i e_\eta\,dt - K_d\,\omega_b$</dd>
</dl>
<div class="tbl"><table>
  <thead><tr><th>Gain set</th><th>$K_p$</th><th>$K_i$</th><th>$K_d$</th><th>Used</th></tr></thead>
  <tbody>
    <tr><td>Aggressive</td><td>5</td><td>6</td><td>0.9</td><td>roll/pitch, no fault</td></tr>
    <tr><td>Mild</td><td>1.4</td><td>1</td><td>0.9</td><td>roll/pitch, after a fault</td></tr>
    <tr><td>Yaw</td><td>0.8</td><td>0.2</td><td>0.6</td><td>always</td></tr>
  </tbody>
</table></div>
<p class="note">D on the measured body rate, so reference steps don't kick. The integral stores $\int K_i e$, so switching sets is bumpless.</p>
</div>
<div class="prop">
<b>Fault-aware allocation</b> <span class="note">(RPIC17 [@rpic17] eq. (6))</span>
<dl class="eq">
  <dt>No fault</dt>
  <dd>$f = \operatorname{clamp}\big(A^\dagger [M; F_z],\ f_{\min},\ F_M\big)$</dd>
  <dt>Motor $i$ off</dt>
  <dd>$f = \tilde A_i^\dagger [M; F_z] + \beta\,w,\quad \tilde A_i w = 0,\ w_i = 0$</dd>
</dl>
<p>$\beta$ is one scalar. Keep $\beta = 0$ if every motor fits in $[f_{\min}, F_M]$, else the smallest $\beta$ that fits; if none does, the least violating one, then clamp.</p>
<p class="note">$f_{\min}$ is the 14 % PWM running floor (ICRIS18 §V): a stopped brushless motor restarts badly. A partial fault $h$ caps the motor at $h F_M$.</p>
</div>

<Section n={4} title="Why tilting helps">

<p class="sub">Motor $i$ sits at $r_i = l\,\hat d_i$, $\theta_i = (i-1)\,60^\circ$, body frame FLU, spinning $\sigma_i = (-1)^{i+1}$.</p>

<dl class="eq">
  <dt>Spin axis</dt>
  <dd>$e_i = \cos\gamma\,\hat d_i + \sin\gamma\,\hat z$</dd>
  <dt>Column of $A$</dt>
  <dd>$A_{:,i} = \begin{bmatrix} r_i \times e_i + \sigma_i \tilde k_t e_i \\ \hat z \cdot e_i \end{bmatrix}$</dd>
  <dt>Wrench</dt>
  <dd>$[M_x, M_y, M_z, F_z]^\top = A f,\quad 0 \le f_i \le F_M$</dd>
  <dt>Tilt parameter</dt>
  <dd>$\alpha = \dfrac{\tilde k_t}{\sqrt3\, l \tan\gamma},\quad \alpha(107^\circ) = -0.068$</dd>
</dl>

With motor 2 off, the thrust column of $\tilde A_2^\dagger$ is

<dl class="eq">
  <dt>Thrust share</dt>
  <dd>$Q = \tfrac{\csc\gamma}{4D}\big[(\alpha{-}1)^2, 0, (\alpha{+}1)^2, D, 4\alpha^2, D\big]^\top$</dd>
</dl>

with $D = 3\alpha^2 + 1$. Every healthy motor gets a positive share [@taes16] exactly when $\alpha \notin \{0, \pm 1\}$, so more thrust can always lift all of them above 0 and any torque is reachable. Flat ($\alpha = 0$): motor 5 gets no share, and one yaw direction would need $f_5 < 0$.

<p class="note">The code builds $A$ from the model's geometry and uses the printed closed forms only as test oracles. $\gamma = 107^\circ$ leans the axes inward like the real vehicle; the papers' $A$ matches at $180^\circ - \gamma$.</p>

</Section>

<Section n={8} title="Against the papers">

- **Reproduced.** RPIC17 [@rpic17] Fig. 7–8: flat + pinv rolls over 1.3 s after the cap, tilted + null space holds. Hover before the fault reads 60 % PWM (paper ≈ 60 %).
- **Reproduced.** ICRIS18 [@icris18] Fig. 6, 11: aggressive gains track, motor 2 at 0, motor 5 lowest and on the floor.
- **Not reproduced.** RPIC17 motor levels after the fault: ours 40 / 41 / 66–72 %, the paper's ≈ 22 / 30–35 / 80 %. That is flight data, so the gap can be sim-to-real.
- **Yaw asymmetry** (ICRIS18 Fig. 12–13): both directions settle; the stressed one is not visibly worse with steps and no noise.

</Section>

<Section n={9} title="Assumptions and limits">

- **PWM → thrust is quadratic**, $f = F_M (u/u_{\max})^2$, fitted to two points (derived). The papers' linear model puts hover at 46 % PWM against 60 % measured, and leaves no hover with motor 5 on the floor.
- **Inertia**: the identified $J_z = 0.1094$ of ICRIS18 [@icris18] breaks $J_x + J_y \ge J_z$, so the model uses $J_z \approx J_x + J_y$.
- **Rotor speed** $\omega_{\max} = 1000$ rad/s is assumed; the papers give none.
- **Not modelled**: sensor noise and an estimator, ground effect, battery sag, motor restart transients.

</Section>
